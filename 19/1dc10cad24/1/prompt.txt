No, there's no existing code in this codebase that would let you backfill the shadow branch (or the committed checkpoint storage) from standalone .jsonl transcript files. Here's what I found after going through the repo:
What exists:

entire doctor — Can condense stuck sessions that already have a shadow branch and session state file (.git/entire-sessions/<id>.json). It won't help if the shadow branch was never created in the first place.
CondenseSessionByID — The internal method doctor uses. It still requires an existing SessionState and ideally a shadow branch at entire/<commit[:7]>-<worktreeHash[:6]> with the transcript already stored under .entire/metadata/<session-id>/full.jsonl. It can fall back to a live transcript path, but that path has to be in the session state.
WriteCommitted on checkpoint.GitStore — This is the low-level API that writes directly to the entire/checkpoints/v1 branch. It accepts a WriteCommittedOptions struct with transcript bytes, session ID, checkpoint ID, files touched, etc. This is the closest thing to an "import" primitive, but it's a Go API, not a CLI command.

What's missing:
There's no entire import, entire backfill, or any CLI command that takes a .jsonl file path and writes it into the checkpoint storage. The entire pipeline assumes the hooks were active during the session — the Start hook creates the session state, SaveStep writes to the shadow branch on each tool use, and the post-commit hook triggers condensation.
If you wanted to build a backfill:
The most viable path would be to write a small Go program (or extend the CLI with a new command) that:

Takes a .jsonl transcript file and the commit hash it corresponds to
Generates a CheckpointID via id.Generate()
Calls checkpoint.GitStore.WriteCommitted() with the transcript bytes, extracted prompts (using extractUserPromptsFromLines), a synthesized session ID, and the relevant metadata
Optionally amends the corresponding git commit to add the Entire-Checkpoint: <id> trailer for bidirectional linking

All the building blocks exist in the codebase — WriteCommitted, extractUserPrompts, calculateTokenUsage, generateContextFromPrompts — they're just not wired up into any "import from file" workflow.
