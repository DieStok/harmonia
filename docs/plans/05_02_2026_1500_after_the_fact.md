## Root Cause Analysis

**Why Beaker showed `/build`, `/src` etc. instead of workspace folders:**

The Beaker file browser displays the container's working directory (`/jupyter`), which contains the baked-in source code from when the container was built. The `/workspace/data` and `/workspace/results` bindings from `exec_apptainer_harmonia.sh` **were actually mounted correctly**, but:
- The file browser only shows the working directory contents
- The agent CAN access `/workspace/data` and `/workspace/results` via Python code
- But there was no environment variable or prompt telling the agent about these paths

## Issues Encountered

### Issue 1: Host Python Too Old
When `exec_apptainer_harmonia.sh --monitor` tried to run `run_manual_experiment.py`, it used the host's Python 3.6 which lacks the `dataclasses` module (added in Python 3.7).

**Error:**
```
ModuleNotFoundError: No module named 'dataclasses'
```

**Resolution:** Modified `exec_apptainer_harmonia.sh` to run the monitor script inside the Apptainer container using the same Python environment as Beaker.

### Issue 2: Monitor Requires Active Session
The `ManualExperimentRunner` tried to connect immediately after Beaker started, but Beaker doesn't create a session until a user opens the web UI.

**Error:**
```
No active Beaker session found. Start Beaker first with: ./exec_apptainer_harmonia.sh
```

**Resolution:** Modified `manual_runner.py` to poll for sessions with a 5-second interval, waiting up to 1 hour for the user to open the browser.

## Changes Made

### 1. `exec_apptainer_harmonia.sh`

- Added `--data-dir` and `--results-dir` command line arguments
- Changed binding paths from `/workspace/data` and `/workspace/results` to simpler `/data` and `/results`
- Added `DATA_DIR=/data` and `RESULTS_DIR=/results` environment variables for the container
- In `--monitor` mode, auto-creates experiment-specific results directory: `results/<experiment_name>_<timestamp>/`
- Runs monitor script via Apptainer to use Python 3.11 instead of host Python

### 2. `run_manual_experiment.py`

- Added `--start-server` flag to launch Beaker server as subprocess
- Added `--global-results` flag for backward compatibility
- Default behavior now uses experiment-specific output directories
- Note: When using `--start-server`, the script manages the full lifecycle

### 3. `src/automation/manual_runner.py`

- Modified `_connect_to_kernel()` to wait for session creation
- Polls every 5 seconds for up to 1 hour
- Provides user feedback about waiting for browser connection

## Recommended Approach for Manual Experiments

**Best Practice (Single Command):**
```bash
srun --partition=gpu --gpus-per-node=1 --time=04:00:00 --mem=64G --cpus-per-task=8 \
    ./exec_apptainer_harmonia.sh \
    --config experiments/experiment_1_harmonia_dou2020_gdc/configs/manual/dou_harmonization_manual_devstral-small.yaml \
    --monitor
```

This will:
1. Create experiment-specific results directory
2. Start Ollama and preload the model
3. Start Beaker server
4. Run the monitor (waiting for you to open the browser)
5. Log all interactions to the results directory
6. Clean up everything when you press Ctrl+C

**What the LLM Sees Inside Container:**
- `/data/` - Read-only access to all datasets
- `/results/` - Read-write access to experiment-specific output directory
- `/jupyter/` - Baked-in source code (working directory)

**Tell the LLM:**
```
The input data is at /data/one_metadata_table_gdc_schema/data/dou.csv
Save any outputs to /results/
```
