# LLM-based metadata harmonization for omics: state of the art and benchmark design

**Large language models have fundamentally altered the landscape of schema matching and metadata harmonization, yet a critical gap persists: no rigorous benchmark exists for evaluating these systems on real-world omics metadata from repositories like GEO.** The field has progressed from classical string-matching approaches achieving near-zero F1 on complex biomedical schemas to LLM-based systems reaching 72–82% hit rates on healthcare benchmarks — but these gains have not been validated in the omics domain, where free-text metadata, implicit context, and deep ontological structures create distinct challenges. This report synthesizes 25 years of schema matching research (2001–2026), catalogs every major system with its architecture and benchmark performance, and provides a concrete blueprint for designing the first comprehensive GEO metadata harmonization benchmark. The central finding is that **hybrid retrieval-then-rerank architectures combining small language models with frontier LLMs currently define the state of the art**, but their superiority over classical methods has been demonstrated only on clinical (MIMIC-OMOP) and cancer genomics (GDC) benchmarks — not on the heterogeneous, free-text-heavy metadata that characterizes GEO.

## PART 1: A taxonomy of schema matching approaches spanning 25 years

### Classical matchers collapse on complex biomedical schemas

The first generation of automated schema matching systems, developed between 2001 and 2005, established foundational algorithms that remain in active use as baselines. **COMA/COMA++** (Do & Rahm, 2002/2005) introduced the composite matching paradigm, combining **15+ individual matchers** — including string-based name similarity, WordNet synonym matching, data-type comparison, constraint-based matchers, and a reuse-oriented matcher leveraging previous match results — through configurable combination strategies (max, average, weighted). The NamePath+Leaves configuration, which combines hierarchical path similarity with leaf-node comparison, was the recommended default. COMA 3.0 extended this with OWL ontology support, fragment-based decomposition for large schemas, and a GUI. It remains available as a Java application on SourceForge (COMA 3.0 Community Edition) and as a Python wrapper in the Valentine framework (`valentine.algorithms.Coma`). On Valentine's fabricated benchmarks, COMA performs competitively for lexically similar schemas, but **on the MIMIC-III-to-OMOP complex task, it achieves only F1 = 0.04** — effectively random.

**Cupid** (Madhavan et al., 2001) implemented a two-phase approach: linguistic matching via tokenization, abbreviation expansion, and thesaurus-based synonymy, followed by structural matching that propagates similarity bottom-up through schema trees. Despite its theoretical elegance, Cupid has become the weakest baseline in modern evaluations. Magneto (VLDB 2025) explicitly excluded it from reporting because it "consistently performed significantly worse than the other methods." On MIMIC-OMOP, Cupid produces F1 near zero. Its failure stems from over-reliance on lexical similarity, making it unable to bridge semantic gaps where column names differ substantially. It survives today only as a Python reimplementation in Valentine.

**Similarity Flooding** (Melnik et al., 2002) takes a fundamentally different approach: it converts schemas into directed labeled graphs, builds a pairwise connectivity graph, and iteratively propagates similarity scores through fixpoint computation — conceptually similar to PageRank. The algorithm captures structural similarity that element-level matchers miss, but at computational cost of O(n² × k) where n is the number of node pairs and k is the number of iterations. On MIMIC-OMOP complex tasks, it achieves **F1 = 0.09** — modestly better than COMA but still far below LLM-based methods. Valentine provides a Python implementation with configurable coefficient policies (inverse_product, inverse_average) and formula variants.

The **Valentine framework** (Koutras et al., ICDE 2021) unified these systems into an extensible evaluation platform with five built-in matchers: COMA, Cupid, SimilarityFlooding, DistributionBased, and JaccardLevenMatcher. Valentine's central empirical finding — that **no single matcher dominates across all scenarios** — has been confirmed by every subsequent study. The framework provides fabricated dataset pairs with four relatedness semantics (Unionable, View-Unionable, Joinable, Semantically-Joinable), available on Zenodo. However, Valentine's datasets are predominantly lexical in nature, containing matches like "Gender" → "Ge" and "Employer" → "Em" that are uncommon in real applications. The framework's true value is as infrastructure: it is pip-installable, supports batch matching for data lakes, and serves as the standard harness for evaluating new methods.

**Unicorn** (Tu et al., SIGMOD 2023) represented the pre-LLM machine learning frontier: a unified multi-task model using DeBERTa-base (139M parameters) with a Mixture-of-Experts layer supporting seven matching tasks (entity matching, schema matching, string matching, column type annotation, ontology matching, entity linking, knowledge graph matching). It achieves an impressive **94.56 average score across 20 datasets** but has a critical limitation: Magneto found that "the zero-shot version performed significantly worse than other baselines and was excluded from evaluation." Unicorn was trained on Valentine's fabricated datasets, giving it an advantage on those specific benchmarks but poor generalization to out-of-distribution biomedical data.

### Embedding approaches established transformers as the new baseline

**DeepMatcher** (Mudgal et al., SIGMOD 2018) defined the design space for deep learning entity matching with four architectures (SIF, RNN, Attention, Hybrid), each following an attribute-embedding → comparison → classification pipeline. The Hybrid model, combining bidirectional GRU with cross-attention, achieved the best results. On the ER-Magellan benchmark, deep learning was competitive with Magellan on structured data (**87.9% vs. 88.8% F1**) but dramatically superior on textual (+3–22% F1) and dirty data (+6–33% F1). DeepMatcher's code is on GitHub but the project appears discontinued.

**Ditto** (Li et al., VLDB 2021) demonstrated that fine-tuned pretrained transformers could substantially advance entity matching. Using DistilBERT (or BERT/RoBERTa) with structural serialization tags (`[COL]...[VAL]...`), domain knowledge injection via NER, TF-IDF summarization for long entries, and MixDA data augmentation, Ditto achieved **an average 9.43% F1 improvement over DeepMatcher+** across 13 ER-Magellan datasets (up to 32% on specific datasets). Crucially, Ditto does not require entries to share the same schema and achieves comparable performance with only **20% of labeled data**. It remains available at GitHub (Megagon Labs) and represents the bridge between classical ML and the LLM era.

For biomedical applications, domain-specific embeddings prove essential. **SapBERT** (Liu et al., NAACL 2021) fine-tunes PubMedBERT using UMLS's 4M+ biomedical concepts via multi-similarity loss, self-aligning representations so that all aliases of a UMLS entity cluster together. It achieves state-of-the-art on six medical entity linking benchmarks (Acc@1 = 0.718 with reranking on BioNNE-L) and substantially outperforms PubMedBERT on entity-level tasks. SapBERT is freely available on HuggingFace (MIT license) and is now used as a retrieval component in multiple hybrid systems, including the multi-agent GEO curation system (bioRxiv, June 2025) and RELATE.

The **Alzheimer's Disease Harmonization Text Embedding Benchmark (ADHTEB)** (Adams et al., *J Prev Alzheimers Dis*, January 2026) delivers a finding with direct implications for this field: **general-purpose embedding benchmarks like MTEB do not predict domain-specific harmonization performance**. The study evaluated five embedding models — including three top-ranked on MTEB as of August 2025 — on harmonizing seven Alzheimer's disease cohort datasets to a clinical common data model. Models that ranked highly on MTEB performed worse than expected on clinical variable matching. The authors released an open-source benchmark library (GitHub: SCAI-BIO/ADHTEB) and an interactive leaderboard, establishing a new paradigm: domain-specific benchmarks are non-negotiable for evaluating harmonization systems.

Within the Magneto system, ablation studies show that **MPNet outperforms RoBERTa and E5** as the SLM retrieval component for schema matching. After fine-tuning with LLM-generated synthetic data, MPNet combined with LLaMA3.3-70B reranking achieves the highest overall MRR of **0.860** on the GDC benchmark. The current MTEB leaders — Qwen3-Embedding-8B, Gemini embedding-001, Voyage-3-large — have not been systematically evaluated for schema matching, and the Adams et al. finding suggests their general rankings would not transfer.

### LLM-based systems achieve order-of-magnitude gains through retrieval-then-rerank

**Magneto** (Liu et al., VLDB 2025) established the dominant architecture for LLM-based schema matching: a two-phase pipeline where a small language model (SLM) retrieves candidates and a large language model (LLM) reranks them. The SLM (MPNet by default) generates column embeddings via serialization that includes column name, table name, description, and up to **10 sample values per column** — empirically optimal. Candidates are retrieved via cosine similarity, then the top-k are sent to the LLM (GPT-4o-mini or LLaMA3.3-70B) with a score-based prompt that elicits individual match scores (0.00–1.00) rather than just rankings, enabling cross-pair comparison.

The self-supervised fine-tuning mechanism is Magneto's key innovation: LLMs generate syntactically diverse synthetic training data (column name paraphrases, value variants) that is used to fine-tune the SLM via contrastive learning with triplet loss. Once fine-tuned, the SLM runs independently without LLM calls. On the **GDC-SM benchmark** — 10 CPTAC cancer study datasets (covering pancreatic, renal, endometrial, lung, head/neck, breast, ovarian, colon, and brain cancers) matched to 736 GDC target columns — the best configuration (fine-tuned MPNet + LLaMA3.3-70B) achieves **MRR = 0.860** and **Recall@GT = 0.537**. The GDC benchmark is available on Zenodo (DOI: 10.5281/zenodo.14963588), and Magneto's code is fully open-source at GitHub (VIDA-NYU/magneto-matcher) with pre-trained GDC retrievers on HuggingFace. **Magneto has not been applied to GEO metadata**, though its architecture is directly applicable.

**LLMatch** (Wang et al., APWeb-WAIM 2025) introduced the first framework explicitly designed for multi-table schema matching. Its three-stage architecture — schema preparation (with Rollup), table selection, and column matching (with Drilldown) — addresses the context window problem that plagues single-prompt approaches. **Rollup** consolidates semantically related target columns into higher-order abstract concepts using LLM inference, reducing schema complexity. **Drilldown** re-expands these concepts for fine-grained mapping. The novel **SchemaNet benchmark** provides 7 source-target schema pairs across healthcare (MIMIC-OMOP, Synthea-OMOP, CMS-OMOP, CPRD Aurum-OMOP, CPRD Gold-OMOP), finance, and entertainment domains, averaging **14 tables and 135 columns per dataset** — far larger than typical benchmarks. On MIMIC-to-OMOP, LLMatch achieves F1 of 0.30–0.85 across table pairs (vs. COMA's 0.04). Code is available at GitHub (knowledge-fusion/LLMatch).

**Matchmaker** (Seedat & van der Schaar, NeurIPS GenAI for Health Workshop 2024) pioneered the compositional LM program approach. Its three-stage architecture is distinctive: (i) target schema attributes encoded as multi-vector documents using **ColBERTv2** token-level embeddings; (ii) **dual candidate generation** combining semantic retrieval AND reasoning-based candidates — a refiner LLM narrows these; (iii) confidence scoring via **MCQ format** with a "None of the above" abstain option. The self-improvement mechanism, inspired by DSPy's BootstrapFewShot, automatically generates synthetic in-context demonstrations from the model's own successful traces without human labels. On MIMIC-OMOP, Matchmaker achieves **acc@1 = 62.20% (±2.40)** and on Synthea-OMOP **70.20%**, outperforming ReMatch, Jellyfish, LLM-DP, and SMAT. The critical sub-finding is that reasoning-based candidates outperform semantic-only retrieval, and that the IR formulation requires only ~1,340 LLM calls versus ~24,771 for binary classification — **O(n) vs. O(n²)**. A significant limitation: **code has not been publicly released**, hindering reproducibility. Independent reproduction attempts (Oregon State, 2025) note that "Matchmaker fails when the LLM does not follow the required format in intermediate steps."

**SCHEMORA** (Gungor et al., July 2025) currently holds the highest reported hit rates on MIMIC-OMOP: **HitRate@3 = 72.05%** (vs. Matchmaker's 68.8%) and **HitRate@5 = 80.39%** (vs. ReMatch's 72.9%). Its approach is deceptively simple: use LLMs to generate enriched/alternative column names via Chain-of-Thought prompting (two complementary prompts — one expanding names with context, one generating alternatives excluding original words), then build hybrid indices (FAISS vector + BM25 full-text search) over enriched names. The best configuration uses **GPT-4.1 + text-embedding-3-large + 3 generated names per column**. SCHEMORA is notable as the **first LLM-based schema matching method with fully open-source code** (GitHub: ermangungor/schemora).

**ConStruM** (Chen et al., January 2026) addresses a subtler problem: how to pack the most discriminative evidence into a fixed-budget prompt. Its "context tree" organizes schema metadata in a coarse-to-fine hierarchy, and a "global similarity hypergraph" captures groups of confusable columns. For each matching decision, ConStruM assembles a compact "context pack" with multi-level neighborhood summaries and contrastive differentiation cues that highlight what distinguishes similar columns. On **HRS-B** (a new context-stress benchmark using the Health and Retirement Study), ConStruM achieves **accuracy = 0.935 vs. ReMatch's 0.503** — demonstrating that structured context massively outperforms raw context on disambiguation-heavy tasks. It uses GPT-5 for all LLM calls.

**ReMatch** (Sheetrit et al., 2024) established the retrieval-enhanced single-LLM-call paradigm: serialize schema elements as structured passages, embed via Ada2 (OpenAI), retrieve top-J target tables, and make a single GPT-4 call per source attribute group. It achieves acc@1 of ~54–56% on MIMIC-OMOP — a strong baseline that all subsequent systems build upon. **No public code release** has been made.

**Jellyfish** (Zhang et al., EMNLP 2024) represents the fine-tuning approach: instruction-tuned 7–13B models (OpenOrca-Platypus2-13B, Mistral-7B, Llama 3-8B base) via LoRA for data preprocessing tasks including schema matching. Despite being fine-tuned on MIMIC and Synthea datasets, **Jellyfish-13B achieves only 15.36% acc@1** — a dramatic underperformance explained by its binary pairwise classification formulation that doesn't scale to large target schemas. Models are available on HuggingFace.

**BDI-Kit** (Lopez et al., *Patterns* [Cell Press], February 2026) takes a different approach as an open-source Python toolkit for biomedical data harmonization, providing APIs for schema matching, value matching, and data transformation. It integrates Magneto's matching engine with a human-in-the-loop design featuring confidence scores and an interactive chatbot-style agent interface for domain experts. The toolkit is pip-installable (`bdi-kit`, v0.9.0, Apache 2.0) and represents the most deployment-ready system. **Harmonia** (Santos et al., arXiv, February 2025) extends this with an agentic paradigm where LLM agents synthesize data harmonization pipelines interactively.

**Parciak et al.** (VLDB TaDA Workshop 2024) provided the most systematic study of prompt design effects on schema matching. Their key finding is a **context sweet spot**: performance suffers from both too little context (1-to-1 scope: one source, one target attribute) and too much (N-to-M scope: all source and target attributes). Intermediate scopes (1-to-N, N-to-1) perform best. Additional findings: newer LLM versions increase decisiveness (fewer "unknown" responses), a 3-step scale (yes/no/unknown) outperforms 5-step scales, and majority voting across 3 runs reduces hallucination. Their benchmark (49 valid matches across 1,839 attribute pairs on MIMIC-IV to OMOP) and code are publicly available on GitHub.

**Narayan et al.** (*PVLDB* 16(4), 2022) authored the foundational study demonstrating that foundation models can wrangle structured data. Using GPT-3 with zero-shot and few-shot prompting, they matched or outperformed existing ML methods on **11 of 14 benchmark datasets** across five data wrangling tasks. This paper — cited by virtually all subsequent schema matching work — established that LLMs trained only on unstructured text can handle structured data tasks without fine-tuning. Code and datasets are available at GitHub (HazyResearch/fm_data_tasks).

Two additional recent systems merit attention. **SMoG** (arXiv, November 2025) uses iterative 1-hop graph queries on knowledge graphs for schema matching, achieving F1 = 41.67% on CMS data — competitive with vector-based approaches while offering storage efficiency and explainability. A **test-time reinforcement learning agent** (EMNLP 2025 Industry Track) dynamically discovers and accumulates evidence from external sources at inference time without model updates, using confidence as a proxy reward signal.

### Value mapping remains the unsolved half of harmonization

Value mapping — transforming free-text metadata values to controlled vocabulary terms — is fundamentally different from schema matching and substantially harder. While schema matching asks "which column maps to which column?", value mapping asks "how should 'NSCLC tumor, left lower lobe' be standardized to the GDC enumeration value 'Lung'?"

For **biomedical ontology alignment**, **MILA** (Information Fusion, 2025) currently defines the state of the art. It embeds an LLM within a Prioritized Depth-First Search strategy: fast lexical/embedding-based retrieval resolves high-confidence matches without LLM invocation, and only borderline cases escalate to the LLM. On OAEI Bio-ML biomedical tracks, MILA achieves **F1 = 0.83–0.95** while reducing LLM query volume by over **90%**. **MapperGPT** (arXiv, 2023) combines high-recall lexical mapping (via OAK Lexmatch) with GPT-4 semantic refinement, achieving highest F1 on anatomy matching with near-perfect recall, though overall accuracy plateaus at approximately **67%**. **BERTMap** (AAAI 2022) fine-tunes BioClinicalBERT on synonym corpora constructed from within-ontology and cross-ontology label pairs, outperforming LogMap and AML on biomedical alignment.

For **GDC-specific value mapping**, the task is a constrained generation/selection problem: the GDC data dictionary defines **200+ enumerated properties** across ~40 nodes, with thousands of distinct permissible values anchored to NCIt concepts and caDSR Common Data Elements. Properties like `primary_diagnosis` contain hundreds of ICD-O-3 morphology codes; `therapeutic_agents` lists hundreds of drug names. The constraint that values must exactly match case-sensitive strings from a defined set makes this amenable to retrieval-augmented constrained generation — but even with LLMs, Magneto's results show GDC matching accuracy is significantly lower than for simpler domains.

**A critical gap exists: no standardized benchmark evaluates instance-level value mapping to controlled vocabularies.** OAEI evaluates concept-level ontology alignment. Schema matching benchmarks evaluate column correspondences. But the specific task of mapping "Ca.," "Carcinoma," "tumor," and "Neoplasm" to a standardized ontology term has no established evaluation framework. The closest work is Verbitsky et al.'s (Bioinformatics Advances, 2025) evaluation of fine-tuned GPT-2 models achieving **96% in-dictionary accuracy but only 17% out-of-dictionary accuracy** — a 79-point gap that underscores how poorly current models generalize to unseen terminology.

### The omics domain gap is real and measurable

Seven concrete papers now apply LLMs to omics/GEO metadata, collectively revealing both promise and fundamental challenges.

**Verbitsky, Boutet & Eslami** (*Bioinformatics Advances*, 2025) fine-tuned GPT-2 models with realistic data augmentation (typos, abbreviations, word reordering) to map researcher-specific synonyms to standardized terms across cancer (NCIt), alcohol research, and infectious disease (NCBI Taxonomy) domains. Their finding that **domain-specific small models outperform zero-shot GPT-4o** on specialized terminology is crucial for benchmark design, though the **17% OOD accuracy** highlights how far value mapping still has to go.

**"Toward Total Recall"** (Sundaram, Gonçalves & Musen, *GigaScience*, 2025) directly compared BioSample and GEO metadata standardization using GPT-4 with and without CEDAR templates. The results are stark: GPT-4+CEDAR achieves **82% recall for BioSample but only 44% for GEO**. The 38-point gap is attributable to three factors: (1) GEO lacks a dedicated CEDAR template, so BioSample templates were repurposed; (2) GEO's lengthy free-text values cause the LLM to deviate — for instance, generating "NSCLC tumor" instead of "lung"; (3) GEO lacks a structured data dictionary comparable to BioSample's. This paper provides the strongest evidence that **GEO metadata is fundamentally harder than other biomedical repositories**.

**EMBERS** (Higashi et al., bioRxiv, October 2024) combined semantic clustering with LLM-driven NLP to extract and standardize metadata from gut microbiome papers and supplementary tables, achieving a **50% recovery rate** over 400,000 samples — significantly outperforming rule-based methods but still missing half of curated metadata.

A **multi-agent AI system** (bioRxiv, June 2025) targets single-cell/single-nucleus RNA-seq from GEO, using dedicated agents including an ontology reasoning agent that combines SapBERT/PubMedBERT dense retrieval, TF-IDF sparse matching, and ontology graph traversal (synonym/parent/child). **h5adify** (bioRxiv, March 2026) takes a neuro-symbolic approach, combining deterministic biological inference with locally deployed LLMs (Gemma, Llama, Mistral, Qwen via Ollama) to harmonize AnnData objects, demonstrating that small local models achieve high semantic accuracy with low hallucination rates and modest computational requirements.

**Long et al.** (bioRxiv, November 2025) provide the most comprehensive documentation of what manual curation actually involves: **212,027 samples across 468 studies** from curatedMetagenomicData and cBioPortal, revealing pervasive quality issues — typos, inconsistent terminologies, misplaced values, conflicting annotations (including 303/337 sex discordances from a single study). **Lim et al.** (*Database*, 2021) curated 10,811 GEO transcriptomic datasets with 10,215 distinct terms from 12 ontologies — a multi-year effort representing the largest manually curated transcriptomic resource.

What makes omics metadata categorically harder than financial or entertainment data? **Context-dependence** (the same term like "normal" means different things across studies), **implicit metadata** (critical information exists only in publications or supplementary tables), **free-text heterogeneity** (GEO enforces no controlled vocabulary), **multi-modal complexity** (genomics, transcriptomics, proteomics each have different vocabulary conventions), **deep ontological structures** (UBERON alone has thousands of terms with subtle distinctions), and **conflicting annotations** that require domain expertise to resolve. These challenges compound: a harmonization system must not only match column names but interpret context, resolve ambiguity, and map free-text values to deeply nested ontology branches.

Biological ontologies are increasingly made accessible to LLMs through four mechanisms. **RAG approaches** like OntologyRAG (IQVIA) and DRAGON-AI (*J Biomedical Semantics*, 2024) retrieve ontology concepts via embedding similarity and feed them to LLMs. **Ontology-constrained prompting** via CEDAR templates or GDC YAML schemas specifies acceptable value sets per field. **Tool-use agents** employ OAK (Ontology Access Kit) — a Python library providing unified API access to OWL, OBO, BioPortal, and OLS backends — to programmatically traverse ontology hierarchies. And **hybrid agents** combine all three: the multi-agent GEO curation system uses SapBERT for dense retrieval, TF-IDF for sparse matching, and ontology graph traversal simultaneously. The comprehensive review "Large Language Models in Bio-Ontology Research" (PMC, 2025) confirms that **hybrid methods consistently outperform either deterministic or LLM-only approaches**.

## PART 2: Blueprint for a GEO metadata harmonization benchmark

### Five task levels ordered by increasing complexity

A rigorous benchmark must decompose the harmonization problem into measurable components. The following five task levels form a progression from atomic operations to end-to-end pipelines:

**Task Level 1 — Single-table schema matching to GDC.** Given one source metadata table (e.g., a GSM characteristics table from a single GEO series) and the GDC data dictionary, identify which source columns correspond to which GDC properties. This is the task Magneto's GDC-SM benchmark evaluates, with 10 CPTAC datasets mapped to 736 GDC target columns. Metrics: Precision, Recall, F1 for exact match; MRR and Recall@K for ranked evaluation. Minimum benchmark size: **200+ ground truth column matches** across at least 10 diverse source tables (covering different cancer types, tissue types, and metadata styles) for adequate statistical power to detect F1 differences of 0.10 (per power analysis below). Gold standard requires ≥3 independent expert annotators with target Cohen's κ ≥ 0.60.

**Task Level 2 — Single-table schema matching plus value mapping.** Extends Level 1: for each matched column pair, transform the source values to valid GDC enumeration values. This is where the "NSCLC tumor" → "Lung" problem lives. Metrics: exact match accuracy for enumerated fields; semantic similarity (Resnik's measure via NCIt hierarchy) for partial credit; BLEU and Character Error Rate for string fields. A value mapping gold standard requires expert curation of source-value → target-value pairs, with clear handling of unmappable values (null, ambiguous, out-of-scope). The GDC's 200+ enumerated properties with case-sensitive permissible values define the target constraint space.

**Task Level 3 — Two-table harmonization.** Given two source tables from different GEO series studying the same disease, harmonize both to GDC and ensure consistent mappings (e.g., if "gender" maps to `demographic.gender` in table A, the same mapping must hold for table B's "sex" column). Metrics add cross-table consistency scores: percentage of semantically equivalent source columns that receive identical target mappings.

**Task Level 4 — N-table harmonization (N = 5–10).** The realistic scenario: harmonize metadata from multiple GEO series into a unified GDC-compliant dataset. This tests whether systems maintain consistency at scale and handle the combinatorial explosion of cross-table dependencies. LLMatch's SchemaNet benchmark (averaging 14 tables per dataset) provides a structural template.

**Task Level 5 — End-to-end search and harmonization.** Given a biological query (e.g., "lung adenocarcinoma RNA-seq studies with treatment metadata"), search GEO, retrieve relevant series, extract metadata tables, harmonize to GDC, and produce a unified analysis-ready dataset. This is the ultimate goal but requires combining information retrieval, metadata extraction, and harmonization.

### Constructing gold standards that withstand scrutiny

Gold standard construction is the bottleneck determining benchmark quality. For schema matching, the standard process requires **multiple independent domain expert annotators** followed by adjudication. The MIMIC-OMOP gold standard required **500 hours from two experts** — illustrating both the cost and the need for this investment. For GEO metadata, annotators must hold dual expertise: understanding both GEO's free-text conventions and GDC's formal data model.

Inter-annotator agreement should be measured via **Cohen's κ** (for 2 annotators) or **Krippendorff's α** (for 3+, handling missing values). Schema matching typically achieves "substantial" agreement (κ = 0.61–0.80) on surface-level matches but only "moderate" agreement (κ = 0.41–0.60) on semantic matches requiring domain knowledge. The benchmark should report and analyze disagreement rates, using a mediating third annotator for resolution and treating residual disagreement as a signal of inherent ambiguity rather than annotation error.

For value mapping evaluation, "close but not exact" mappings require **graded scoring**. A three-tier scheme works: full credit for exact match, partial credit (weighted by ontological distance via Wu-Palmer or Resnik similarity in NCIt) for semantically related matches, zero credit for unrelated mappings. For multi-table evaluation, a **tree similarity metric** (adapted from OAEI) can assess structural consistency across mapped table sets.

Several existing curated GEO metadata collections could seed gold standard construction. **CREEDS** provides 4,205 curated GEO signatures (single-gene perturbation, disease, drug) with controlled vocabulary annotations. **STARGEO** offers 42,950 annotations across 1,084 tags mapped to Disease Ontology terms for 47,503 GEO experiments. **Gemma** (Lim et al., 2021) contains 10,811 manually curated GEO datasets with 10,215 ontology terms. **OmicsMLRepo** (Long et al., 2025) provides explicit original_value → curated_ontology_term mappings for 212,027 samples. None of these were designed as schema matching benchmarks, but their curated mappings could be reverse-engineered into ground truth.

**Statistical power analysis**: to detect an F1 difference of 0.05 at power = 0.80 and α = 0.05 using McNemar's test with ~10–20% discordant proportion, approximately **400–800 test instances** (column matches) are needed. For F1 differences of 0.10, **100–200 instances** suffice. MIMIC-OMOP's 155 gold matches are borderline for detecting small effects; a GEO benchmark should target **400+ ground truth matches** across 20+ source tables.

### A systematic comparison methodology spanning all paradigm generations

The benchmark must compare systems across three generations with consistent evaluation:

**Classical baselines** via Valentine: COMA (NamePath+Leaves configuration), Cupid, SimilarityFlooding, DistributionBased, JaccardLevenMatcher. These establish the floor performance and are essential for calibrating how much LLM-based methods improve over simple approaches.

**Embedding baselines**: MPNet (Magneto's default, demonstrated best in schema matching ablations), E5-large-v2, BGE-M3, PubMedBERT, SapBERT. These test whether domain-specific biomedical embeddings (SapBERT, PubMedBERT) outperform general-purpose models on omics metadata — the Adams et al. finding predicts they should.

**LLM-based systems** in three tiers. Frontier: Magneto (GPT-4o-mini + fine-tuned MPNet), SCHEMORA (GPT-4.1 + text-embedding-3-large), LLMatch (Rollup/Drilldown), BDI-Kit agent, Matchmaker reimplementation (if code becomes available). Mid-tier: systems using Claude Sonnet, GPT-4o-mini, or Gemini Flash. Local: LLaMA 3.3-70B (shown to achieve MRR = 0.860 in Magneto), Qwen 2.5-72B, Mistral Large, and quantized 8B models (the Oregon State study showed 4-bit quantized Llama-3-8B can match GPT-4 Matchmaker performance with better pipeline design).

**Frontier coding agents** as baselines: Claude Code and ChatGPT Codex in full-auto mode, given the source/target schemas and data samples, asked to produce mapping code. **No published study has compared general coding agents to specialized schema matching tools** — this would be a novel contribution of the benchmark.

Statistical comparison should follow Demšar's (2006) recommendations: **McNemar's test** for single-dataset pairwise comparisons, **Wilcoxon signed-rank test** across multiple datasets, **Friedman test with Nemenyi post-hoc** for comparing all systems simultaneously, with **Bonferroni correction** (α_adjusted = α/m where m = k(k-1)/2 for k systems). Always report **95% confidence intervals via bootstrap** and **Cohen's d effect sizes**.

### The experimental variable space requires principled prioritization

Eleven variable categories affect LLM schema matching performance. Based on the literature, they should be tested in this priority order (which also reflects estimated effect size):

**Priority 1 — agent architecture/pipeline formulation.** The choice between binary classification (O(n²), Jellyfish-style), retrieval-then-rerank (O(n), Magneto-style), compositional LM program (Matchmaker-style), and coding agent (CodeAct) represents the single largest performance driver. Jellyfish's **15.36% acc@1** vs. Matchmaker's **62.20%** on identical data demonstrates the scale of this effect.

**Priority 2 — candidate generation strategy.** Matchmaker's finding that dual-source candidates (semantic retrieval + LLM reasoning) outperform either alone, combined with SCHEMORA's finding that metadata enrichment is the most critical component, establishes this as the second-largest effect.

**Priority 3 — LLM choice.** Within the retrieval-then-rerank paradigm, model choice matters: Magneto shows LLaMA3.3-70B (MRR 0.860) outperforms GPT-4o-mini (MRR 0.815). But the Oregon State finding that smaller models with better techniques can match GPT-4 suggests model choice interacts strongly with pipeline design.

**Priority 4 — context content** (per ConStruM). Structured evidence packing with context trees and differentiation cues dramatically outperforms raw context on disambiguation tasks (0.935 vs. 0.503 on HRS-B). This variable is testable via ablation within any pipeline.

**Priority 5 — number of example values.** Magneto's ablation shows 10 values is optimal; more values introduce noise without improving matching. Priority sampling (favoring frequent values) enhances performance over uniform sampling.

**Priority 6 — schema representation.** Full GDC (736 columns) vs. pruned (relevant clinical nodes only) vs. few-shot (description + examples). Parciak et al.'s context sweet spot finding — performance suffers from both too little and too much context — applies here.

**Priority 7 — ontology access method.** None vs. embedded descriptions vs. RAG over ontology vs. tool-accessible via OAK API. The "Toward Total Recall" finding that GPT-4+CEDAR (ontology-constrained) achieves 97% adherence vs. GPT-4 alone's 80% establishes this effect for value mapping.

**Priorities 8–11** — temperature (lower preferred for schema matching), multi-turn vs. single-turn (bidirectional matching with symmetric transformations improves robustness), prompt optimization (DSPy-optimized vs. manual vs. random in-context examples), and context window management strategies — have smaller estimated effects and can be tested in parallel within the higher-priority configurations.

## PART 3: A failure mode taxonomy for deployment

### Six categories of failure with measured frequencies

**Category 1: Schema matching failures.** Wrong mappings occur when LLMs exploit surface lexical similarity rather than semantic meaning — mapping "admission_time" to "visit_start_date" when the correct target is "visit_start_datetime," or mapping "stage" (disease stage) to a staging-system column. Hallucinated targets arise when LLMs confidently propose columns that don't exist in the target schema, especially when queried about schemas likely in their training data (Parciak et al.'s data contamination concern). **Many-to-one collapse** occurs when multiple semantically similar source columns are merged into a single target; SCHEMORA notes ReMatch is constrained to 1:1/m:1 and cannot handle many-to-many mappings present in Synthea-OMOP. Compositional failures cascade through multi-step pipelines: Matchmaker "fails when the LLM does not follow the required format in intermediate steps." Estimated frequency: wrong mappings affect **20–40%** of column pairs on complex schemas (based on MIMIC-OMOP acc@1 ranges of 60–72%).

**Category 2: Value mapping failures.** Incorrect ontology code generation is measured directly: GPT-3.5/GPT-4 achieve **under 50% accuracy** for ICD-9/10 and CPT codes from text descriptions. Hallucinated values are documented in the "Toward Total Recall" paper: GPT-4 changed correct "blood" tissue to "lung" when other metadata mentioned lung cancer. Format errors are pervasive: LLaMA-3 and MedLLaMA-2 produce "frequent formatting errors requiring extensive post-processing." The 79-point gap between in-dictionary (96%) and out-of-dictionary (17%) accuracy in Verbitsky et al. reveals the fundamental fragility of value mapping.

**Category 3: Context-dependent failures.** Biomedical metadata requires implicit knowledge that LLMs may lack or misapply. The "Toward Total Recall" paper demonstrates that GEO's free-text values cause LLMs to deviate from expected values (generating "NSCLC tumor" instead of "lung"). Domain misinterpretation is especially dangerous in omics: "normal" can mean healthy tissue, adjacent-normal tissue, or normalized data depending on experimental context. LLMs trained on general corpora may not distinguish FIGO staging from AJCC staging without explicit context.

**Category 4: Multi-table failures.** Inconsistent cross-table mappings arise when independent per-table processing yields contradictory results — "sex" → `demographic.gender` in one table but "gender" → `demographic.sex` in another (where GDC uses "gender" as the canonical field). Merge conflicts occur when two tables use the same column name for different concepts. LLMatch's Rollup/Drilldown mitigates some of these failures but adds its own: over-abstraction during Rollup can merge genuinely distinct columns.

**Category 5: Agent-level failures.** Multi-turn conversation degradation is measured: models show an average **39% performance drop** in multi-turn settings, forming premature assumptions in early turns and failing to recover. "Ceremonialization" — where the model claims to have verified results without actually doing so — is particularly insidious for harmonization where correctness verification requires ontology lookups. Degeneration loops in autoregressive generation produce self-reinforcing repetition. Poorly defined tool descriptions are identified as "the leading cause of agent failure" in production deployments.

**Category 6: Infrastructure failures.** Token limits constrain how much schema context can be provided. The GDC target schema has 736 columns — serializing all of them with descriptions and value examples would exceed most context windows. Rate limiting and model unavailability affect production reliability. Cost unpredictability arises from the 10-100x price range across models (DeepSeek V3.2 at $0.14/M input tokens vs. GPT-5 at $10/M).

### Ten actionable deployment guidelines

Based on the cumulative evidence across all reviewed systems, these guidelines represent the highest-confidence recommendations:

1. **Use retrieval-then-rerank, never binary classification.** The architecture choice from O(n²) to O(n) is the single largest performance lever. Magneto, SCHEMORA, and Matchmaker all demonstrate that candidate retrieval followed by LLM reranking dramatically outperforms exhaustive pairwise comparison — in both accuracy and cost.

2. **Constrain LLM outputs with templates and valid value sets.** GPT-4+CEDAR achieves 97% adherence vs. 80% without templates. For GDC value mapping, always provide the enumerated permissible values in the prompt and enforce exact-match validation on outputs.

3. **Fine-tune a domain-specific retrieval model.** Magneto's self-supervised fine-tuning (using LLM-generated synthetic data to train MPNet) improved GDC MRR from 0.551 to 0.860. The Adams et al. ADHTEB finding that MTEB rankings don't transfer to domain-specific tasks makes this non-optional.

4. **Include exactly 10 sample values per column using priority sampling.** This empirically optimal number (Magneto ablation) provides enough distributional signal without introducing noise. Priority sampling — favoring frequent values — enhances matching likelihood.

5. **Use dual candidate generation (semantic + reasoning).** Matchmaker's finding that reasoning-based candidates capture matches that pure semantic retrieval misses is confirmed by ConStruM's demonstration that structured context outperforms raw similarity on disambiguation tasks.

6. **Implement human-in-the-loop for confidence below threshold.** Even SCHEMORA's 80.39% HitRate@5 means ~20% of mappings are wrong at rank 5. BDI-Kit's architecture — automated matching with confidence scores and interactive refinement — is the correct deployment pattern. Route all sub-threshold predictions to domain expert review.

7. **Validate cross-table consistency for multi-table harmonization.** Run a post-processing pass that checks whether semantically equivalent source columns across tables receive identical target mappings. Flag inconsistencies for human review.

8. **Test with local models before committing to API costs.** The Oregon State finding that quantized Llama-3-8B with bidirectional matching achieves accuracy comparable to GPT-4 Matchmaker, plus h5adify's demonstration that local Gemma/Llama/Mistral achieve high accuracy for metadata harmonization, suggests local models may be sufficient for many tasks while eliminating API dependency and enabling privacy-preserving deployment.

9. **Run multiple prompts with symmetric transformations and aggregate.** Randomly permuting column order, sampling different values, and running bidirectional (source→target and target→source) matching — then aggregating via majority voting or score multiplication — reduces sensitivity to prompt structure and provides confidence estimates.

10. **Build domain-specific benchmarks before deployment.** The Adams et al. principle applies broadly: do not assume that a system performing well on MIMIC-OMOP will perform well on GEO metadata. Create a GEO-specific test set with expert-curated gold standards before deploying any system, using the existing curated resources (CREEDS, STARGEO, Gemma, OmicsMLRepo) as starting materials.

## Conclusion: the field is racing ahead but omics benchmarking lags behind

The central tension in LLM-based metadata harmonization is between rapid methodological progress and the absence of domain-appropriate evaluation. Systems have advanced from COMA's F1 = 0.04 to SCHEMORA's HitRate@5 = 80.39% on MIMIC-OMOP in under three years — but every one of these measurements was made on clinical healthcare schemas, not omics metadata. The "Toward Total Recall" study's finding that **GEO recall (44%) trails BioSample recall (82%) by 38 points** under identical LLM conditions is the most important number in this report: it quantifies the omics domain gap that no current benchmark captures.

Three insights emerge that should guide benchmark design. First, the hybrid retrieval-then-rerank paradigm is settled science — the debate has shifted to what retrieval and reranking strategies work best, not whether this architecture is correct. Second, value mapping is the harder unsolved problem: schema matching at 72–82% hit rates is approaching practical utility, but value mapping at 17–50% accuracy for out-of-domain terms is not. A GEO benchmark that evaluates only schema matching misses the harder half. Third, the most impactful benchmark would use real GEO series metadata mapped to GDC by domain experts — leveraging OmicsMLRepo's 212,027 curated samples and Gemma's 10,811 annotated datasets as starting materials — and evaluate the complete pipeline from raw GSM characteristics to GDC-compliant records with ontology-grounded values. The existing GDC-SM benchmark (Magneto, 10 CPTAC datasets) provides the structural template; what remains is extending it to GEO's uniquely challenging free-text metadata.
