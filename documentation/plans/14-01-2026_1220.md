# Bug Fix Plan: BDIKit Context Tools Not Available

## Date: 2026-01-14 12:20

---

## Executive Summary

The primary issue is that **bdikit_context tools are not available** to the Beaker agent despite the context switching appearing to work. Root cause analysis reveals that:

1. **Entry points are not properly registered** when using `pip install -e` at runtime
2. Beaker discovers contexts via `importlib.metadata.entry_points(group="beaker.contexts")`
3. Entry points are only registered during a proper `hatch build` wheel creation
4. The runtime `pip install -e /jupyter` doesn't go through the full Hatch build hook

```python
def autodiscover(mapping_type: ResourceType) -> typing.Dict[str, type]:
    group = f"beaker.{mapping_type}"  # e.g., "beaker.contexts"
    eps = entry_points(group=group)   # Uses importlib.metadata
    items: AutodiscoveryItems = AutodiscoveryItems(eps)
```

**Key insight**: Beaker uses Python's standard `entry_points()` mechanism which reads from installed package metadata.

## Root Cause Analysis

### Issue: "Context has no workflows: disabling tools"

**NOT the real problem.** This message is informational, not an error. Workflows are optional.

### Issue: Tools not available to agent

**Real problem.** The bdikit_context package is not properly discovered because entry points aren't registered.

**Evidence from logs:**
```
Switching from context default to bdikit_context...
Context switch complete.
Context 'bdikit_context' set successfully
```

The context *name* is recognized (from the `%set_context` magic), but the actual `BDIKitContext` class is not loaded because entry points aren't found.

### Why entry points aren't registered

Current `jupyter.def`:
```
%post
    uv pip install --system --no-cache -e /jupyter
```

**Problem**: `pip install -e` (editable install) doesn't write entry points to the system's metadata database the same way a wheel install does. It creates a `.egg-link` file instead of proper `dist-info/entry_points.txt`.

---

## Fix Plan

### Option A: Build wheel and install it (Recommended)

**Steps:**
1. In `jupyter.def`, build the wheel with `hatch build`
2. Install the wheel (not editable) with `pip install dist/*.whl`

**Advantages:**
- Entry points properly registered
- Standard installation path
- No editable install complications

### Option B: Install beaker_kernel hook dependencies and use hatch develop

**Steps:**
1. Install beaker_kernel with its build tools
2. Run `hatch develop` instead of `pip install -e`

**Disadvantages:**
- More complex
- Still may have issues with entry point discovery

### Option C: Manual entry point registration (Fallback)

Create a JSON mapping file in the Beaker library locations.

**Disadvantages:**
- Legacy method (generates deprecation warnings)
- Requires knowing the exact paths

## Implementation: Option A

### Step 1: Update jupyter.def

Replace:
```
%post
    uv pip install --system --no-cache -e /jupyter
```

With:
```
%post
    cd /jupyter
    # Build the wheel (this runs the Beaker build hook and generates entry points)
    hatch build
    # Install the built wheel
    uv pip install --system --no-cache /jupyter/dist/*.whl
```

### Step 2: Verify entry points

After rebuild, verify with:
```bash
apptainer exec jupyter.sif python -c "from importlib.metadata import entry_points; print([ep.name for ep in entry_points(group='beaker.contexts')])"
```

Expected output: `['bdikit_context']`

### Step 3: Rebuild Apptainer image

```bash
srun -J apptainer_build --time=02:00:00 --mem=80G --gres=tmpspace:100G bash build_apptainer.sh
```

### Step 4: Verify context loading

```bash
apptainer exec jupyter.sif beaker dev watch --ip 0.0.0.0 --port 8888 &
# In Python client:
# %set_context bdikit_context python3 {}
# Context should now have tools available
```

## Secondary Issues

### Issue: 405 Method Not Allowed on POST /notebook

**Status**: Low priority, doesn't affect experiment execution

**Root cause**: The Beaker server's `/notebook` endpoint may only support GET requests.

**Evidence**:
```
405 POST /notebook?token=... (Method Not Allowed)
```

**Impact**: Notebooks not saved during experiment, but results still captured in trace.json

**Potential fix**: Investigate Beaker server handlers in `/beaker_kernel/service/handlers.py`

### Issue: Empty LLM responses from Ollama

**Status**: Related to context tools issue

**Root cause**: Without tools, the agent has no functions to call, so it returns empty responses.

**Evidence**: All turns complete in <1s with empty responses - the LLM has nothing to do.

**Fix**: Will be resolved when context tools are properly loaded.
